# Fix: Worker Node Bootstrap Race Condition & Join Failures

## Summary

During `terraform apply`, worker nodes launched in parallel with the
control plane and attempted to join before it was ready, causing
cluster-wide join failures. Root-caused to four interdependent issues
across Terraform sequencing, join-command networking, user-data size
limits, and containerd config generation.

## Symptom

```
error execution phase preflight: couldn't validate the identity of the API Server
context deadline exceeded
```
2/2 worker nodes failed to join; ~2 hours to resolve.

## Root Cause

1. **Terraform dependency gap.** Terraform marks `aws_instance.control_plane`
   complete as soon as AWS assigns an instance ID — seconds after launch,
   long before the 3–5 minute `user_data` bootstrap finishes. Workers
   launched immediately and polled SSM before the join parameter existed.
2. **Join command pointed at the public NLB.** `kubeadm token create
   --print-join-command` used `controlPlaneEndpoint` (the public Network
   Load Balancer DNS). Workers in private subnets hit NAT Gateway
   hairpin-routing limits and Security Group drops trying to reach it.
3. **`user_data` exceeded EC2's 16,384-byte limit** once the control-plane
   script grew, causing `terraform apply` to reject the instance.
4. **containerd 2.x schema mismatch** on `SystemdCgroup` — same root cause
   as `README-containerd-systemdcgroup-fix.md`.

## Resolution

1. **Gate worker creation on control-plane readiness** with a polling
   `null_resource`:
   ```hcl
   resource "null_resource" "wait_for_control_plane" {
     depends_on = [aws_instance.control_plane]
     provisioner "local-exec" {
       command = <<EOT
         until aws ssm get-parameter --name "${local.ssm_join_command_path}" --region "${var.aws_region}" >/dev/null 2>&1; do
           sleep 10
         done
       EOT
     }
   }

   resource "aws_instance" "worker" {
     count      = var.worker_count
     depends_on = [null_resource.wait_for_control_plane]
   }
   ```
2. **Build the join command against the private IP explicitly**, instead
   of relying on `controlPlaneEndpoint`:
   ```bash
   JOIN_CMD="kubeadm join $${NODE_IP}:6443 --token $${JOIN_TOKEN} --discovery-token-ca-cert-hash sha256:$${DISCOVERY_HASH}"
   ```
3. **Compress `user_data`** to stay under the size limit:
   ```hcl
   user_data_base64 = base64gzip(templatefile("${path.module}/templates/control_plane.sh.tftpl", { ... }))
   ```
4. **containerd fix** — already covered by the whitespace-tolerant `sed`
    + diagnostic dump in `README-containerd-systemdcgroup-fix.md`.

## Verification

- [ ] Fresh `terraform apply` from a clean state: workers do not start
  until the SSM join parameter exists.
- [ ] Join command generated by control plane targets the private IP,
  not the public NLB DNS.
- [ ] `terraform plan`/`apply` succeeds with the gzipped `user_data`
  under the 16 KB limit.
- [ ] Worker nodes reach `Ready` state without preflight identity errors.

## Follow-ups

- **Join token TTL:** still on default (24h). Needs a decision before
  adding an ASG — either `--ttl 0` (non-expiring) or a rotation
  mechanism. Flagged, not yet resolved.
- **Control-plane health endpoint:** current gate only checks that the
  SSM parameter exists, not that the API server is actually healthy.
  A dedicated readiness check (SSM doc or S3 flag) would be more
  precise than inferring readiness from the join parameter alone.
